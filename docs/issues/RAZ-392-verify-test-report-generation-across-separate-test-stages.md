# RAZ-392 — Verify test report generation across separate test stages

Test plan connected to [RAZ-84](https://linear.app/alosha/issue/RAZ-84/see-before-booking) to verify that actual automated test runs generate complete reports in the intended folders.

## Stage 1: Configuration

Inspect Vitest, Playwright and CI settings. Confirm test commands, enabled reporters and output paths. Identify CI-only reports.

Pass: Each report has a verified command and destination.

## Stage 2: Missing folders

Run tests with the relevant output folder absent. Recreate missing required folders if the runner does not create them.

Pass: The test run can write to the intended destination. An empty folder alone does not pass.

## Stage 3: Unit tests

Run Vitest with coverage enabled and inspect `coverage/`, subject to configuration verification.

Pass: Generated HTML and JSON reports are readable and contain results from the actual run.

## Stage 4: E2E tests

Run BDD tests and applicable design/visual suites. Inspect `playwright-report/`, `playwright-report/design/` and the configured result directories. Verify paths against configuration rather than assuming they exist.

Pass: HTML reports open and contain actual test results. Check design reporting in CI if required by configuration.

## Stage 5: Freshness and CI

Repeat the test run and verify that reports update. Check CI artifact upload and download.

Pass: Reports belong to the latest run, and downloaded CI reports are readable.

## Acceptance

A complete report exists in the verified destination and was generated by an actual test run, not manually created or left over from an earlier run. Record test failures separately from report-generation failures: failed tests may produce a valid report, but a run blocked before report generation does not satisfy acceptance.
